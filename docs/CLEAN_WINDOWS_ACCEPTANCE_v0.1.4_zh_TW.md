# MSH v0.1.4 CPU 候選版：乾淨 Windows 驗收

此包供內部驗收，尚非正式公開 Release。MSH 安裝及啟動不需要 Python、Git 或 Conda。
套件不提供模型、研究影像、標註或 dataset。正式發佈仍待授權、原始碼版本及 B 地驗收完成。

## 測試環境與檔案

- 使用未安裝開發用 Python／Git 的 Windows 10／11 64 位元測試電腦或乾淨 VM。
- 本機開發電腦的安裝成功，不能代替這項測試。記錄實際 Windows 版本與測試帳號類型。
- 此流程不連接相機、COM、Arduino、XY 或馬達。B 地硬體驗收另行執行。
- 候選安裝檔：`MSH_Setup_v0.1.4_CPU_CANDIDATE.exe`，229,093,351 bytes。
- SHA-256：`236bcc28e3e66b6f1828efc740fb73b21ab5b95b176422a76fb767a32d5cb388`。
- 安裝檔目前未簽章。若系統防護阻擋，記錄狀況並停止；不要為測試關閉防護。

需要核對雜湊時，可使用可信任的 SHA-256 工具，或在檔案所在資料夾使用 Windows 內建 PowerShell：

```powershell
Get-FileHash -LiteralPath .\MSH_Setup_v0.1.4_CPU_CANDIDATE.exe -Algorithm SHA256
```

這只是驗收時核對檔案的方式，不是啟動 MSH 的必要步驟。

## 驗收步驟

1. 核對安裝檔大小、SHA-256 與相鄰的建置 manifest，填寫驗收表。
2. 確認測試帳號沒有既有 MSH 安裝或需要保留的同名捷徑。若有，先記錄並改用乾淨環境。
3. 用一般使用者帳號執行安裝程式，記錄安裝目錄、是否要求管理員權限及是否要求重新開機。
4. 從開始功能表啟動 MSH，確認不依賴開發用 Python／Git；「說明 → 關於 MSH」應顯示 `v0.1.4`。
5. 確認啟動時沒有選定模型，畫面提示提供本機模型；X/Y 顯示未連接，預覽未啟動。
6. 如有可合法使用的本機相容 `.pt` 模型，將它放在安裝目錄之外，測試「選擇模型」及「清除模型」。
   僅選取檔案不等於完成模型載入或推論；沒有模型時填「未測」，不要下載或上傳模型來補此步。
7. 不啟動預覽、連線或任何移動按鈕。正常關閉 MSH，確認視窗與該程序結束，再重新開啟一次。
8. 關閉 MSH 後，在自管測試資料夾與 `Documents\MSH` 放入不含研究內容的測試文字檔。
   記錄其內容或 SHA-256；若有自備模型，也先記錄模型雜湊。
9. 執行同一候選版覆蓋安裝，確認版本、啟動與上述使用者檔案保持正常。
10. 關閉 MSH，從 Windows 應用程式清單解除安裝；確認應用程式與新建捷徑移除，步驟 8 的檔案及外部模型保留。
11. 填寫 `VALIDATION_RESULT_zh_TW.md`。失敗時保留本機 `%LOCALAPPDATA%\MSH\msh.log`；回報前移除個人路徑或敏感資訊。

## 已知範圍與限制

- 本機已完成實際安裝、同版覆蓋安裝、解除安裝、資料保留及舊版遷移測試；本表仍需在乾淨 Windows 實測。
- 封裝 EXE／依賴已透過隔離副本的測試入口完成 `.pt` 合成影像推論與一個 epoch CPU 訓練。
  這不等於原 GUI 的相機辨識流程已驗收，也不代表辨識準確度或安裝版提供訓練 GUI。
- 此 CPU 候選版沒有 `onnx`／`onnxruntime`；即使模型選擇器列出 `.onnx`，也不得記為可用或已驗收。
- 訓練套件在新設定環境可能嘗試下載繪圖字型；隔離測試阻擋該請求後訓練仍完成。未觀察到替代模型下載。
- `latest.json` 尚未發佈，自動／手動更新檢查可能取得 HTTP 404；記錄為已知發行設定狀態。
- 靜默參數 `/NOICONS` 不能保證不產生開始功能表捷徑；請以實際結果驗收。
- 舊版內附模型遷移：先盤點並備份、核對雜湊，解除安裝舊版後再裝新版；不要假定覆蓋安裝會移除舊權重。
- 本驗收包不得當作正式版公開上傳，也不包含本機驗證過程產生的模型或合成資料。

完整證據及仍待完成事項見專案的 `docs/RELEASE_CANDIDATE_v0.1.4.md`。
