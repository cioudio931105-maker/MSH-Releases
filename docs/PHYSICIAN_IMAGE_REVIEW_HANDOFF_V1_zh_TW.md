# MSH 醫師影像檢閱與資料交接 V1

狀態：V1 流程定義（2026-09-03）

## 目的與範圍

本流程供醫師以**影像層級**完成檢閱與分類，將結果安全地交回研究團隊。它不取代診斷、臨床報告、病理資訊系統或 IRB／校方資料治理要求，也不建立或修正 YOLO bounding box。

V1 的交付物位於受控的專案外位置，不得複製到本 repository 或 Git：

- `MSH_醫師檢閱資料庫_20260903`：來源與治理記錄、BBOX 預覽。
- `MSH_醫師影像分類包_20260903`：供檢閱的影像與空白分類資料夾。
- `MSH_醫師快速分類工具.html`：離線影像分類工具；分類包內有鏡像版本。

實際交付給醫師的資料夾必須是獨立的單一批次，例如 `MSH_醫師交付批次_batch_20260903_A01`，並且**只包含待檢閱影像**。資料來源、標註檔、內部來源對照表、歷史輸出、工具、CSV 與操作說明均留在資料管理者端；醫師以另行提供的工具開啟該影像資料夾。

本文件只記錄流程與資料契約；不包含任何病患、血片或影像資料。

## 醫師檢閱流程

1. 研究團隊先確認影像已依研究／醫療規範完成去識別化，並為每個檢閱批次建立非識別化的批次名稱。
2. 資料管理者為每個批次建立一份交接包，將固定批次代碼寫入工具與其 Google Form 預填連結；例如目前交接包使用 `batch_20260903_A01`。不得交付通用工具讓醫師自行猜測或輸入批次名稱。
3. 醫師從該批次的分類包開啟離線快速分類工具，選取唯一的影像根資料夾後逐張檢閱。工具可放大、縮小、拖移、符合畫面、檢視原圖 100%，並可用快捷鍵分類、復原與匯出 CSV。
4. 每張影像只選一個最適合的 V1 分類；不確定或需要討論時，使用對應的例外分類，不要以推測取代判斷。
5. 匯出 CSV 後，按工具的「上傳結果」；Google Form 的批次欄位已預填。醫師只需登入 Google 帳號、填寫檢閱者姓名／代號、選取 CSV、確認無可識別資料並提交。檔案會儲存至 Form 擁有者的 Google Drive。
6. 研究團隊先檢查 CSV 與批次名稱、列數及非識別化要求，再將結果移入對應的受控資料夾；尚未完成檢查的資料不可視為已確認標註或 ground truth。

工具若顯示「原標註提示」，它只表示資料管理者從既有標註整理出的粗略候選類別，並非醫師結論；醫師應依影像本身重新判讀。

Google Form 在發布、分享或變更權限前，必須另取得明確授權。本流程不授權這些動作。

## V1 分類字典

| 類別 | 使用時機 |
| --- | --- |
| `WBC` | 無法可靠分為下列 WBC 亞型，但可判為白血球。 |
| `RBC` | 紅血球為主要可辨識目標。 |
| `Platelet` | 血小板為主要可辨識目標。 |
| `Neutrophil` | 可判為嗜中性球。 |
| `Lymphocyte` | 可判為淋巴球。 |
| `Monocyte` | 可判為單核球。 |
| `Eosinophil` | 可判為嗜酸性球。 |
| `Basophil` | 可判為嗜鹼性球。 |
| `Mixed_cell_field` | 同一視野有多種細胞，無單一主分類可忠實描述。 |
| `Second_opinion_needed` | 醫師無法確定，或需要另一位專業人員共同判讀。 |
| `Non_blood_cell_or_noise` | 非血球、雜訊、偽影或不屬於上述檢閱目標。 |

V1 不提供「BBOX 需修正」或「影像品質不佳」作為醫師分類選項。BBOX 預覽僅供理解資料來源，不得據此推定 BBOX 已獲醫師確認；影像品質或框選問題應於討論說明中具體描述，並由研究團隊走獨立的標註修訂流程。

## CSV 與交回規則

- 使用快速分類工具匯出的原始 CSV；不要刪除欄位、調整列順序或以人工重建檔案。
- V1 CSV 固定欄位為 `reviewer`、`batch_name`、`image_id`、`doctor_category`。`image_id` 僅使用影像檔名，不輸出本機資料夾路徑；同一批次的影像檔名必須唯一且去識別化。
- 檔案應只涵蓋單一檢閱批次，並以批次名稱和檢閱者代號命名，例如 `batch_20260903_A01.csv`。名稱不得含姓名、病歷號、檢體號或其他可識別資料。
- CSV 的影像檔名／識別碼必須能對回該批次的受控來源清單；若發現缺列、重複列或無法對回的 ID，研究團隊應標記為待討論，不得直接併入確認標註。
- Google Form 欄位為：檢閱者姓名／代號、已預填的檢閱批次／資料夾名稱、必填 CSV 檔案、選填討論說明，以及必填的「無可識別資料」確認。上傳前請確認 CSV 和說明文字均未含可識別資料。
- CSV 是檢閱結果紀錄，不是 YOLO label、模型訓練資料或臨床診斷紀錄；未經後續審查不得直接用於模型訓練。

## Shared Drive 建議架構與狀態流轉

在使用者指定的受控 Shared Drive 下，由資料管理者建立並維護以下資料夾。存取權限、保留期限與跨單位分享均須符合校方、IRB 與資料擁有者規定。

| 資料夾 | 可放內容 | 進入條件 | 不得視為 |
| --- | --- | --- | --- |
| `01_新照片收件區` | 新接收、尚未審查的影像 | 已收到，未完成治理檢查 | 可交付醫師的資料 |
| `02_待醫師檢閱` | 已去識別化、已建批次的影像包 | 已完成來源與最小治理檢查 | 醫師已確認標註 |
| `03_醫師結果收回` | Form 收到的原始 CSV | 已核對批次與檔案完整性 | 可直接訓練的資料 |
| `04_已確認標註` | 經研究團隊審查、版本化的結果 | 來源、批次、列數、討論事項已結案 | 自動等同臨床 ground truth |
| `05_需討論案例` | 第二意見、缺漏或分類衝突案例 | 有明確待決問題 | 已定案資料 |
| `06_索引與版本紀錄` | 批次索引、來源／去識別化／版本記錄 | 無影像個資、可供追溯 | 影像的替代備份 |

建議流向：`01_新照片收件區 → 02_待醫師檢閱 → 03_醫師結果收回 → 04_已確認標註`；任何 `Second_opinion_needed`、不一致、缺列或治理疑慮則轉入 `05_需討論案例`。每次狀態改變都應在 `06_索引與版本紀錄`保留批次 ID、來源代號、處理日期、負責角色、結果版本與理由；不得記錄可識別資料。

## 研究團隊接收檢查

在將一份 CSV 標為已確認前，至少確認：

1. 批次名稱與受控資料夾相符，且 CSV 可讀取。
2. 每一列都能對回該批次的影像識別碼，沒有重複或遺漏。
3. 類別只使用本文件的 V1 字典；不確定案例保留於 `Second_opinion_needed` 或討論流程。
4. CSV、檔名與討論說明均無可識別資料。
5. 已記錄接收日期、檢閱者代號、批次版本與審查結果，但不在 Git 儲存實際影像或檢閱結果。

## 與既有 BBOX／訓練流程的界線

既有的 [醫師血片影像標註與 AI 訓練資料準備](DOCTOR_BLOOD_SMEAR_DATA_PREPARATION_zh_TW.md) 處理 BBOX、YOLO label 與訓練前品質門檻；本 V1 則只處理影像層級的醫師分類和交接。兩者若要串接，必須先完成資料治理、版本確認與另行定義的轉換規則。不得因 V1 CSV 已提交，就宣稱任何 BBOX、YOLO label 或模型訓練資料已獲醫師簽核。
