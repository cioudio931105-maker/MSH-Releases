# MSH GUI／馬達相容性與 B 地接續事項

## 先確認實際執行版本

使用者回報：昨日 B 地使用的 MSH GUI 並非 0.1.4，且當地可能有未 commit／push
的程式修改。方向鍵與 GUI 按鍵都未立即造成可見作動；ULN2003 燈有亮，按住很久
才有動作。在 GUI 互換 COM 指派後，X／Y 幾乎都只有正轉能動。

這是使用者觀察，尚未取得當時的來源、EXE、日誌與板上版本，不能把以下 A 地
比對結果直接當作昨日故障根因。互換 GUI COM 指派也不等於完成實體元件交換測試。

到 B 地的順序：

1. 先盤點與備份當地未提交修改、設定及使用者資料；記錄捷徑目標、實際 EXE／
   來源路徑、GUI 版本與 Git 狀態，不直接覆蓋或清除。
2. 核對最新交接 manifest／雜湊，再依專案規則更新所需來源與安裝版；確認
   GUI、driver、共用規則與韌體的配套關係，不把「最新版」當成已完成整合。
3. 優先處理 RELEASE 工作，如實保留尚未完成的整合、授權、乾淨 Windows 與
   B 地硬體驗收狀態。更新版本或建立候選版不代表馬達問題已解決。
4. 再追查本次延遲／正轉可動問題，先核對命令與版本，實體動作仍須另依安全範圍
   核准。不自動 merge、燒錄、改 COM、速度、方向、步距或安全範圍。

## 已確認的程式差異

| 入口 | 目前應用程式來源 | 固定 RPM 配套／影響 |
|---|---|---|
| 主 GUI 連線 | 明確停用舊改速初始化與能力探測，但沒有查驗 `MOTION_POLICY` | 固定分支先唯讀核對契約，不符即關閉連線 |
| driver 預設連線 | 仍可能送 `SPEED_MS 1 700` 探測與 `SPEED_MS 8` | 其他預設呼叫者可能失敗；不能推論主 GUI 一連線就改速 |
| 手動按住移動 | 正向 `RUN CW 0.020`、反向 `RUN CCW 0.020` | 兩版皆相同；此路徑沒有呼叫預熱／回差補償 |
| 持續旋轉測試 | GUI 預設 4 RPM | 固定韌體拒絕不符 0.02 RPM 的要求 |
| 掃描／錄影速度 | WBC 預設 8 ms、錄影可能 250 ms，結束恢復 5 ms | 固定韌體拒絕這些速度；部分入口捕捉錯誤後沿用板上速度 |
| MOVE 等待 | 未另記錄速度時，100 步預設 timeout 為 30 秒 | 固定速度名義約需 73.24 秒；固定 driver 等待約 98.88 秒含餘裕 |
| 掃描補償 | 保留額外 72 步啟動與換軸等路徑 | 固定分支已隔離；此掃描差異不能直接解釋手動按鍵延遲 |
| STOP | 目前分支的 X/Y 韌體釋放線圈，與 GUI 保持通電文案不符 | 固定韌體的 STOP 保持當前線圈，RELEASE 才釋放 |

目前與固定分支的按鍵均正確傳遞 +1／-1；driver 原函式的無硬體探查分別輸出
CW／CCW。每個基準內的 X／Y 韌體在正規化軸別標籤後相同，CW 與 CCW 使用
相反方向符號。未在這兩個來源基準找到反轉被固定成正轉的錯誤。

名義 0.02 RPM、4096 半步／圈約為每半步 0.732422 秒，30 秒約 41 半步。
低速會放大機械空行程造成的可見延遲，但這不是回差量測，也不是增加補償的依據。
韌體的 `HOLD 1` 本身即可輸出一個相位，燈亮不證明已收到 RUN 或正在持續換相。

## 驗證與限制

- A 地執行兩版 driver 的八組情境、共 16 次軟體探查；以記憶體 transport 模擬
  固定契約回覆，封鎖真實 serial 建構。模擬器未執行 Arduino 韌體。
- 既有 `test_legacy_hardware_helpers.py` 六項通過。這確認既有行為，不能當作
  固定韌體相容性或硬體驗收證明。
- AST／靜態檢查確認鍵盤與滑鼠共用手動入口、兩版手動入口不呼叫預熱／補償，
  並核對正反轉映射、X/Y 相序邏輯與候選版來源雜湊。
- 本次沒有開 GUI、連 COM／相機、移動、燒錄或修改任何控制參數。

B 地應區分：反轉命令是否真的送出、回覆是否成功、燈是否反向依序切換、
馬達軸是否轉動，以及平台是否位移。這些觀察才能協助區分版本／通訊、
輸出／接線／供電與機械傳動問題；目前不能定案。

若後續整合固定 RPM，應選取運動相關變更並保留目前無模型政策。不要整份覆蓋
舊分支 GUI；其中仍有早期模型預設／回退行為。整合、實機驗收與正式發佈均未由
本次文件提交完成。
