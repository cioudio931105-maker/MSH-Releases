# 顯微鏡影像拼接 SOP

## 目的

本 SOP 用於目前專案的顯微鏡座標影像拼接。座標只作為排序與分排參考，實際相鄰影像位移由影像內容估算。

目前正式策略：

```text
先拼單一相鄰 pair
再拼成單排 strip
最後把各 strip 拼成完整圖
```

不要只靠固定座標或固定 overlap 直接疊圖，因為馬達 backlash、步數誤差與顯微鏡視野重複紋理都會造成殘影或錯位。

## 檔名規則

影像檔名必須使用：

```text
x_y.jpg
```

範例：

```text
0_0.jpg
0_-4.jpg
0_-8.jpg
10_0.jpg
10_-4.jpg
10_-8.jpg
```

若資料夾內有 `virtual_coordinates.csv`，程式會優先使用 CSV 內的座標與檔名對應。

## 正式拼接流程

1. 依 X 座標分排，例如 `x=0`、`x=10`。
2. 每一排依 Y 座標排序，例如 `0_0 -> 0_-4 -> 0_-8 -> ... -> 0_-40`。
3. 先估算每一組相鄰 pair 的實際位移。
4. 如果 ORB 把位移誤判成接近 0，改用「受限搜尋範圍」重新估算位移。
5. 保留所有影像，不直接跳過問題張。
6. 每一排先獨立拼成 strip。
7. 最後再把不同 X 的 strip 拼成完整圖。

## 異常位移處理

正式策略不是硬跳過，也不是接受 0 位移。

遇到這種狀況：

```text
10_-20 -> 10_-24 被估成接近 0 位移
10_-24 -> 10_-28 被估成接近 0 位移
```

程式會改用受限搜尋，只在合理的垂直步距範圍內找最佳重疊位置。這可以避免顯微鏡細胞圖案太相似時，ORB 被騙到錯誤的 0 位移。

這次 `C:\test` 的補正結果：

```text
0_-20 -> 0_-24：由約 0 px 補正為 x=24, y=412
10_-20 -> 10_-24：由約 0 px 補正為 x=32, y=556
10_-24 -> 10_-28：由約 0 px 補正為 x=32, y=580
```

## 輸出檢查

每次拼接後檢查這些輸出：

```text
pairwise_pairs/
pairwise_strips/
完整拼接圖
preview 圖
metadata json
```

檢查順序：

1. 先看 `pairwise_pairs`，確認每一組相鄰圖是否合理。
2. 再看 `pairwise_strips`，確認每一排是否連續。
3. 最後看完整圖，確認兩排之間是否有明顯錯位。
4. 如果 metadata 內出現 `repair`，代表該 pair 曾經被判定為異常位移並已補正。

## 拍攝注意事項

拼接品質主要取決於拍攝穩定性。

建議：

```text
X 或 Y 移動後先等待馬達完全停止
拍攝間隔多等 100 ms 以上
避免連續拍到馬達尚未停止的畫面
顯微鏡單次移動不要超過目前可穩定控制的 5-10 step
```

若某段仍然無法穩定拼接，優先重拍該段，不要用強制疊圖掩蓋問題。
