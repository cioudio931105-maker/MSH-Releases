# AccelStepper ConstantSpeed：暫時雙馬達 GUI

**目前為未通過顯微可用性驗收的測試版**：2026-11-19 使用者回報 5 步幾乎沒有可見動作，
10 步有延遲且移動仍過快，不易觀察與拍攝。下列軟體測試／編譯通過不代表此問題已解決。

使用者於 2026-11-15 確認以官方最簡單的 ConstantSpeed 範例為基準：
**FULL4WIRE 整步模式、setMaxSpeed(1000)、實際速度 ±50 步／秒、runSpeed()**。
1000 是速度上限，實際運轉是 50 步／秒；此模式不使用加減速。

上游範例沒有 GUI，而且只控制一顆馬達。本版只做必要適配：兩個馬達物件、
已確認的接腳、四個方向按鍵的 USB 傳遞，以及放開停止／正常關閉線圈。
X、Y 只是兩顆馬達的名稱，沒有平台座標或象限計算。原有 MSH GUI 保留。

2026-11-19 新增有限微調後，使用者回報 1 整步時馬達輸出軸有累積轉動，
但平台／影像位移不明顯，並要求移除 1 步選項。目前介面提供 **5／10 整步**，
預設為微調 **5 整步**；沒有加入自動補償或補跑。
它限制每次要求的步數，不改變 FULL4WIRE、每一步的大小或原有 50 步／秒速度；
原有「連續：按住移動」模式保留。**使用微調前須手動燒錄本版配套韌體**，
舊版 ConstantSpeed 韌體及只支援 1 步的第一版微調韌體均不支援新 5／10 步命令。

舊暫時測試版的固定 0.02 RPM、半步模式、ID/ARM 契約、命令序號與心跳
逾時均已移除；本版與舊版暫時測試韌體不相容，需要重新編譯並手動上傳。

## 接線（斷電後更改）

兩顆 5 V 28BYJ-48 各接一片 ULN2003，由同一塊 UNO R3 控制。

| ULN2003 | X 馬達的板子 → UNO | Y 馬達的板子 → UNO |
|---|---|---|
| IN1 | D4 | D8 |
| IN2 | D5 | D9 |
| IN3 | D6 | D10 |
| IN4 | D7 | D11 |
| ＋／VCC | 5V | 5V |
| －／GND | GND | GND |

函式庫內的接腳參數順序是 IN1、IN3、IN2、IN4，因此程式為 (4,6,5,7)
及 (8,10,9,11)；實體接線仍依上表。每顆馬達插入各自驅動板的五線插座。

先依使用者要求以 USB 供電空載測試；兩顆馬達的供電及保持溫度尚未驗證。
遇到重置、USB 斷線、異常發熱或明顯抖動時停止並切斷電源。I/O 腳只接
ULN2003 輸入，不能直接供應馬達電流。

## 開啟與使用

1. 保留原板韌體的來源／備份，先將馬達與顯微鏡平台脫開。
2. Arduino IDE 直接開啟完整的 firmware/msh_basic_xy/msh_basic_xy.ino，
   不必再複製貼上到新草稿。選 UNO 驗證編譯；確認板子及 COM 後才手動上傳。
   上傳會覆蓋板上原程式，本文與編譯測試都不代表已燒錄。
3. 關閉舊測試視窗及序列監控視窗，雙擊根目錄 **啟動_雙馬達測試.bat**。
   新視窗標題為「MSH ConstantSpeed 雙馬達測試（單 UNO）」。
4. 手動選 UNO 的 COM，按「連線」。這只開啟序列埠，不查驗板上韌體。
5. 預設「微調」為 **5 整步**，可在下拉選單選 **10 整步**。按一下任一方向按鈕，
   要求該軸移動選定步數，完成後保持線圈相位。
   按住不連發；等待韌體回覆時四個方向按鈕及步數選單停用，不累積下一串移動。
   放開滑鼠不會取消這一次有限移動；必須放開並再次點擊才能要求下一次。
   「韌體回報完成」只表示軟體步數到達目標，不證明實體馬達／平台確實移動。
6. 選「連續」後，按住任一方向按鈕以 ±50 整步／秒轉動。放開、移出按鈕或
   視窗失去焦點送出停止指令，保留線圈相位。切換模式會先送停止並取消待完成微調。
   微調等待回覆超過 1 秒會報錯、嘗試關閉線圈並關閉 COM，不重送移動；
   此等待上限不是用電腦計時控制位移，也不是韌體心跳或失聯保護。
7. 正常關閉視窗：送出關閉兩軸線圈的指令，再關閉 COM。UNO 本身仍有 USB 電源。

原始碼入口也可從專案根目錄執行：
.venv312\Scripts\python.exe -m msh_app.hardware.basic_motor_gui

此版沒有心跳、韌體逾時或連線身分檢查。**GUI 當掉、被強制結束或通訊中斷時，
UNO 可能繼續轉動，需手動切斷馬達電源。**直接拔 USB 若同時斷電，就沒有保持力。
開啟序列埠可能重置 UNO，不能以保持力承擔懸吊負載。
整步與半步的每步角度不同；尚無極限開關或平台行程驗證，本階段僅作空載測試。

## 最小 USB 對應

115200 baud；每次操作送一個 ASCII 字元，沒有身分握手、心跳或定期重送。
連續模式沿用小寫命令；有限微調使用大寫命令並等待完成／取消回覆。

| 字元 | 動作 |
|---|---|
| a / b | X 前進 +50 / 後退 -50 步／秒 |
| c / d | Y 前進 +50 / 後退 -50 步／秒 |
| A / B | X 前進／後退 1 整步，完成後保持 |
| C / D | Y 前進／後退 1 整步，完成後保持 |
| E / F | X 前進／後退 5 整步，完成後保持 |
| G / H | Y 前進／後退 5 整步，完成後保持 |
| I / J | X 前進／後退 10 整步，完成後保持 |
| K / L | Y 前進／後退 10 整步，完成後保持 |
| s | 停止兩軸，保留線圈相位 |
| q | 停止兩軸並關閉線圈輸出 |

韌體使用相對目標步數與 `runSpeedToPosition()` 完成有限移動，不以主機的 sleep／停止延遲決定步數。
1 步的 A–D 命令只保留舊協定相容性，GUI 不提供 1 步選項。
5／10 步各自使用一個有限命令，沒有由主機重複傳送 1 步命令來湊次數。
微調執行期間收到其他有限命令會忽略，不延長目標、不排隊；停止、連續命令或關閉命令可取消微調。
韌體回覆一行 `STEP DONE` 或 `STEP CANCELLED`。主機一次只保留一個未完成要求，沒有自動補跑或重送。
程式不會在背景續送連續移動。切換方向按鍵前先停止原動作。
「已送出」只是電腦端送出命令，不代表板上已接收或實際轉動。
